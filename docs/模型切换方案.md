# 声刻模型切换方案

## 当前阶段：双模型已接入，进入用户试听

**已确认的事实：**声刻现在使用 `mlx-community/Qwen3-TTS-12Hz-1.7B-Base-8bit`。用户最早给出的 `RVC-Boss/GPT-SoVITS` 是另一套模型和工程；后来提到的 `debpalash/VoiceStudio` 是集成多个引擎的桌面工作台，其默认语音克隆引擎是 `k2-fsa/OmniVoice`。OmniVoice 官方提供独立模型权重及 Python 运行库，并写明支持 Apple 芯片。它与声刻现有的千问模型不同。

**本轮结果：**保留声刻自己的网页、音色库和 MP3 流程。OmniVoice 官方权重已下载到被 Git 忽略的 `.cache/omnivoice-official/`，约 3.0 GB，版本 `c5fdb5ccb189668d56333f77ba2629f4cd7535f4`。两个 safetensors 文件可读取，SHA-256 与 Hugging Face 官方仓库元数据一致。未安装 VoiceStudio 桌面界面，也未把模型或用户录音提交到 GitHub。官方模型权重是 CC-BY-NC，仅限非商业使用；其代码是 Apache 2.0。将来如需商业用途，要先解决模型授权问题。

**本轮实现：**官方 `omnivoice==0.2.1` 装在独立的 `.venv-omnivoice/`，由本地进程运行，与千问共用声刻的参考录音和原文。网页可选择模型；切换到千问时结束 OmniVoice 进程，切换回 OmniVoice 时释放千问模型，避免 16 GB 内存长期同时驻留两套模型。生成记录保留在本机，支持逐条试听、对照原声、下载；新生成的 MP3 经过解码校验。

**本机实测：**用“测试音色 A”同一参考录音、同一中文文案，两模型均生成 MP3；网页端分别选用千问和 OmniVoice 也成功。OmniVoice 首次启动与生成曾用约 50～94 秒，模型保持运行后短句约 9～11 秒；千问短句约 9 秒。两段 OmniVoice 短句的离线识别能捕捉主要内容，但有同音字误识别。

**尚待用户验证：**人物声音像不像、中文自然度、情绪和长文稳定性，必须由用户在网页中试听比较；文件可解码与离线识别不等于音色质量通过。

## 用户试听

运行启动脚本后打开自动弹出的本机网页，在“生成记录”中找到同一文案的千问与 OmniVoice 两条记录，先听原声，再逐条播放。判断哪个更像原声、哪个更自然，以及有没有错字或不完整；试听结论将决定默认模型和下一轮优化方向。
